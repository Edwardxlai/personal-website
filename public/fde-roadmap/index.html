FDE STAGES / P1—P5

FDE 怎样进入这条业务链路

C 回答一个业务动作发生在商品生命周期的什么位置，P 回答 FDE 对它已经理解和推进到了什么阶段

先了解一件商品的完整生命周期

在这三个问题没有弄清楚以前，不急着讨论要做什么 AI 工具

视角CEO 与公司整体经营视角

先回答三个问题

  • 这次看什么业务
  • 从哪里到哪里 从哪里开始，到哪里结束，涉及哪些部门
  • 想改善什么结果 公司希望改善什么结果

看清每个部门参与了什么

展开 C1—C4，把每个部门参与的环节、输入、输出、上下游关系写清楚

视角各业务主管视角

每个部门看到的那一段

  • 运营部 上架、投流、直播、复盘
  • 产品部 企划、开发、打样、商品资料
  • 素材部门 拍摄、剪辑、素材确认

进入一线动作并判断什么值得做

继续问他们点哪里、看什么、根据什么判断，哪里容易出错，出错以后会造成什么影响

视角一线业务人员视角

四类工作，各看各的指标

  • 执行型 频次、数量、单次耗时、错误率
  • 盯盘型 注意力占用、响应速度、漏看的损失
  • 判断型 涉及金额、输入因素、误判代价
  • 数据型 有没有、存多久、更新多快、口径是否一致

让 AI 进入已经确认的业务动作

每天只要在某个板块上做了实际工作，就在工作日志里写清楚做了什么，得到了什么结果

让 AI 进入的顺序

  • 第一版 先做到读取、整理、提醒和生成草稿
  • 稳定之后 业务人员确认运行稳定以后，再逐步开放写操作
  • 遇到边界 读不到数据、规则算不出来或者状态发生冲突时，停下来并通知业务人员

建立可以运行和复盘的系统

和业务人员一起确定系统边界，把工具接进真实流程，再用运行数据继续修改规则和方案

视角系统建立与迭代视角

系统怎样建立和迭代

  • 接入流程 确定系统边界，把工具接进真实流程
  • 运行与复盘 记录运行结果、出现的问题和每次修改
  • 数据回流 把分散的结果整理成下一轮能够使用的信息
  • 自我迭代 用运行数据继续修改规则和方案

COMPANY LEVELS / L1—L5

这家公司整体走到了哪一步

C 和 P 是一个动作一个动作推进的，L 是整家公司的一个数

FDE 的作用区间

这些工作累积起来，才有可能把一家 L1 或者 L2 的公司推到 L3，再为 L4 准备底座

L1

工具化

TOOLING

大多数公司

L2

流程化

PROCESS

少数公司

L3

角色化

ROLE

极少数公司

L4

系统化

SYSTEM

极少数先行者

L5

原生态

AI NATIVE

少量 AI 原生团队

L1工具化

AI 贴在旧流程上，各干各的，买工具、开账号、零散提效

某几个员工自己用上了 AI，但这件事只发生在他一个人身上，他换岗或者离职，这份效率就跟着消失，公司层面看不到任何变化

L2流程化

单点流程翻倍，但组织考核没变，红利被跨部门等待吃掉

某个部门整体用起来，这一段确实快了很多，但整条链路没有一起提速，多出来的产能卡在部门之间的等待里，这一级最容易让人误判：部门内部的数据很好看，公司整体的结果没有动

L3角色化

人和 Agent 编队，产出开始脱离人头，组织问题的起点

Agent 不再只是某个人手里的工具，而是承担了一部分固定职责，有明确的权限边界，从这一级开始，真正的难题不再是技术，而是组织：谁给 Agent 派活，谁为它的结果负责，它做错了又算谁的

L4系统化

AI 进入经营系统，考核、编制和分钱跟着改，真转型开始

AI 不再挂在流程旁边，而是进入经营系统本身，到这一级，公司不是在用 AI 做事，而是按照「有 AI」这个前提重新设计怎么做事

L5原生态

拿掉 AI 业务停摆，组织围绕 Agent 设计，AI 原生企业

把 AI 拿掉，业务直接停摆，因为整个组织本来就是围绕 Agent 建起来的，岗位、协作方式和交付节奏都以此为默认前提

点阵只表达相对多少，不是统计数据

一个动作已经做到 C3—P5，公司仍然可能停在 L2

反过来，公司想从 L2 走到 L3，靠的也不是某一个动作做得多好，而是 C1—C4 里已经有足够多的动作走到了 P4 和 P5，Agent 才有稳定的职责可以承担
